# v1 → v9: 무엇을 고려했고 무엇을 고쳐 나갔나

버전마다 하나의 질문에 답하려고 했습니다. 결과가 좋지 않았던 버전(v4, v5, v7)도 그대로
적었습니다. 그 버전들에서 얻은 진단이 다음 버전의 방향을 정했기 때문입니다.

| 버전 | 질문 | 결론 |
|---|---|---|
| v1 | 가진 자료로 거절을 예측할 수 있나? | 가능하지만 약하다(ROC 0.66). 0.5 기준 재현율 2% |
| v2 | 재현율이 왜 2%인가? | 임계값 문제 + 구분력 문제. 둘을 분리해서 다뤄야 한다 |
| v3 | 라벨과 평가를 믿을 수 있나? | 확정 결과만 쓰고 시간 순으로 나누자. 0.642 → 0.676 |
| v4 | 심사 사례 지식을 넣으면 나아지나? | 거의 안 나아진다(+0.0001). 채택 안 함 |
| v5 | 근거 규칙을 더 정교하게 넣으면? | 적용되는 사건이 너무 적다. 배포 안 함 |
| v6 | 선행상표와의 충돌을 직접 재면? | 가장 큰 개선. 0.676 → 0.703 |
| v7 | 발음·요부까지 보면? | 검색은 좋아졌지만 예측은 떨어졌다(0.700) |
| v8 | v7은 왜 떨어졌나? | 원인 두 가지를 실험으로 분리해 복구. 0.708 |
| v9 | 실제 거절 사건의 인용상표가 왜 검색 안 되나? | 공고일 누락. 근거 있는 것만 보완 |

수치는 모두 2024년 출원에 대한 ROC-AUC이며, v3부터는 같은 28,588건(±1건)으로 비교했습니다.

---

## v1 — 기준선: 일단 끝까지 만들어 보기

**고려한 것**
- 원자료는 문자열 그대로 보존하고(출원번호 앞자리 0), 출원번호만으로 중복 제거하지 않기.
  같은 출원이 상품류별로 여러 행이라 번호·상품류·출원일·이름의 복합키를 썼습니다.
- 2024년을 최종 평가로 떼어 두고, 그 자료는 설정·사전·모델 선택에 쓰지 않기.
- 무엇이 효과가 있는지 보기 위한 단계별 실험: A(이름 형태) → B(+전체 이름 유사도) →
  C(+주요부) → D(과거 풀 제외 대조), 그리고 DT / RF / XGBoost / AdaBoost 비교.

**결과**: C + XGBoost 선택. 2024년 32,490행 ROC-AUC 0.657, PR-AUC 0.316.
그런데 **확률 0.5 기준 거절 재현율이 2.3%**였습니다. 거절 6,321건 중 144건만 잡은 셈입니다.

**남은 문제**: 재현율이 왜 이렇게 낮은지 설명하지 못했습니다.

## v2 — 진단: 임계값 문제와 구분력 문제를 나누기

**알아낸 것**
- 확률을 보정하면 평균 예측이 실제 거절률(24%)에 맞춰집니다. 그러면 0.5를 넘는 예측은 거의
  없어집니다. 모델이 고장 난 것이 아니라 **보정된 확률에 0.5라는 기준을 그대로 쓴 것**이 문제였습니다.
- 하지만 임계값만의 문제도 아니었습니다. 보정 전후 ROC-AUC는 0.631로 같았습니다.
  순위를 매기는 능력 자체가 약했습니다.

**고친 것**
- 판정 기준을 "0.5 이상"에서 **"거절 사건의 80%가 포함되는 검토 권고선"**(약 0.19)으로 바꿨습니다.
  재현율 78.7%, 정밀도 29%, 검토 대상 65%. 보정을 풀어서 숫자를 올리는 방법은 쓰지 않았습니다.
- 소멸 상표 자료(D, 93,280행)를 선행상표 풀에 추가: 개발 교차검증 ROC-AUC 0.627 → 0.641.

**배운 것**: "재현율이 올랐다"와 "모델이 좋아졌다"는 다른 말입니다. 이후 모든 버전에서
순위 지표(ROC/PR)와 확률 지표(Brier), 정책 지표(재현율)를 따로 보고했습니다.

## v3 — 라벨과 평가 설계를 다시 세우기

**문제의식**: v1·v2의 라벨에는 '출원공고' 상태가 등록 쪽으로 들어가 있었고, 5-fold 교차검증은
미래 출원으로 과거를 예측하는 구조였습니다.

**고친 것**
- **확정 결과만 라벨로**: 등록(등록결정 + 등록번호·등록일) 또는 거절(거절결정). 공고·포기·
  부분결정은 제외. 256,826건 → 약 24만 건.
- **시간 순서 분할**: 2017–21 학습 / 2022 확률 보정 / 2023 모델 선택 / 2024 비교.
- **같은 상표의 기간 간 중복 제거**: 원출원 관계와 정규화한 이름으로 사건군을 만들고, 뒤 기간에
  다시 나오는 앞 기간 사례를 뺐습니다.
- 모델을 문자 TF-IDF(이름 2–4gram, 자모 3–5gram, 지정상품) + 로지스틱 회귀로 단순화.
  어휘와 IDF는 학습 기간에만 맞췄습니다.
- 역할 사전(산지·원재료·상품명 등)은 **2017년 이전 지정상품에 실제로 나온 단어만** 남겼습니다.
  심사 사례에서 뽑은 단어를 그대로 쓰면 결과를 아는 단어가 섞이기 때문입니다.
- 평가 전에 `protocol.json`으로 규칙을 고정하고, 선택 후 모델 해시를 동결.

**결과**: 같은 28,589건에서 v2 0.642 → v3 0.676, PR-AUC 0.323 → 0.359.

**남은 문제**: v3는 선행상표와의 충돌을 전혀 보지 않습니다. 이름과 상품의 글자 패턴만 봅니다.

## v4 · v5 — 심사 사례 지식을 넣어 보기 (효과 없음)

**시도**: '쭈꾸미슐랭'처럼 유명 명칭을 연상시켜 거절된 사례를 모델이 놓쳤습니다. 의견제출통지서·
거절결정서에서 표현 관계(표기·음역·연상)와 근거 규칙을 뽑아 지식 DB로 만들고 특징으로 넣었습니다.

**누수 통제**: 지식 기준일을 2022-01-01로 고정하고, 조회 출원보다 먼저 나온 **다른 사건**의 근거만
쓰도록 했습니다. 쭈꾸미슐랭 자신의 문서를 쭈꾸미슐랭 예측에 쓰지 않았습니다.

**결과**
- v4: 0.67621 → 0.67629. Brier·AUC 차이의 신뢰구간이 0을 포함.
- v5: 근거 규칙 12개, 특징 18개. 새 특징이 켜지는 사건이 학습 224건·평가 38건뿐. 차이 없음.
- v5-r2: PDF 23개를 더 넣었지만 2025년 자료에서 개선이 재현되지 않음.

**배운 것**: 사건별 지식은 조회·설명에는 유용하지만, 25만 건 규모의 예측에서는 적용 범위가 너무
좁습니다. 특정 사례의 숫자를 올리려고 계수를 손대지 않았고, **개선이 확인되지 않은 버전은 배포하지
않는다**는 원칙을 세웠습니다. 그리고 방향을 "지식 추가"에서 "선행상표 검색"으로 돌렸습니다.

## v6 — 선행상표 충돌을 직접 재기 (가장 큰 개선)

**생각**: 거절 사유의 다수는 "먼저 출원된 비슷한 상표가 비슷한 상품에 있다"입니다. 그렇다면
그 정도를 직접 숫자로 만들면 됩니다.

**만든 것** (`prior_search.py`)
- 조회 출원일보다 **출원일과 공고일이 모두 이른** 선행상표만 후보. 현재 상태(등록/소멸)는 읽지 않음.
- 문자 2-gram, 자모 3-gram 역색인으로 후보를 모으고 정밀 유사도 계산.
- 지정상품 겹침: 내 상품 중 후보에도 있는 비율, Jaccard, 상품명 문자 Dice.
- **이름 유사도 × 상품 겹침을 같은 후보 안에서 곱하기.** "이름이 가장 비슷한 상표"와 "상품이 가장
  겹치는 상표"를 따로 골라 곱하면 존재하지 않는 충돌이 만들어집니다.
- 특징 22개. XGBoost(TF-IDF는 64차원으로 압축) + 로지스틱 회귀 혼합.

**결과**: 0.676 → **0.703**, PR-AUC 0.360 → 0.399. 2025년 0.659 → 0.693.

**남긴 한계**: 공고일은 "기록상 공개 시점"일 뿐이고, 출원 당시의 지정상품·권리 존속 여부는 복원할 수
없습니다. 점수가 올랐어도 "완전한 시점 재현"이라고 쓰지 않았습니다.

## v7 — 발음·요부 검색 (검색은 개선, 예측은 하락)

**문제의식**: 실제 심사문서 107건을 읽어 보니 인용상표가 문자로는 달라도 발음이 같거나
(DAVID/데이빗), 이름의 일부(요부)만 같은 경우가 많았습니다.

**만든 것** (`phonetic.py`, `pair_search.py`)
- 영어는 CMU 발음 사전, 한글은 로마자 변환으로 소리열을 만들고 유성/무성 등을 느슨하게 합침.
- 띄어쓰기·문자 종류 경계와 보통명칭 제거로 요부 후보 생성.
- "사전에 없는 이름"을 식별력의 근거로 쓰던 특징(`kb_unmatched`) 제거.
- 선행상표 유사도가 높을수록 거절 확률이 내려가지 않도록 단조 제약.

**결과**: 인용상표 검색 Recall@10은 9.4% → 24.0%로 올랐지만, 2024년 ROC-AUC는 0.703 → **0.700**으로
내려갔습니다.

**배운 것**: 검색이 좋아지는 것과 예측이 좋아지는 것은 별개입니다. 하락을 그대로 보고하고
원인 분석을 다음 버전의 과제로 삼았습니다.

## v8 — 왜 떨어졌는지 실험으로 분리하기

같은 시드·같은 학습 행으로 조건을 하나씩만 바꿔 2023년 자료에서 비교했습니다.

| 조건 | 트리 ROC-AUC (2023) |
|---|---:|
| v7 그대로 (단조 제약 있음) | 0.6834 |
| 단조 제약만 제거 | 0.6883 |
| + v6의 선행상표 특징 22개 복원 | 0.6928 |

**원인**
1. v7은 새 특징 10개를 넣으면서 v6의 22개를 **교체**했습니다. 로지스틱 갈래에는 선행상표 특징이
   아예 빠져 있었습니다.
2. 단조 제약이 맞지 않았습니다. 검색 유사도는 '충돌의 정답'이 아니라 근사치라서, 방향을 강제하면
   오히려 손해였습니다.

**고친 것**: 두 특징군을 합치고(32개) 제약을 빼고 두 갈래 모두에 연결. 후보 목록을 학습 전에
`protocol.json`에 적어 두고 2023년 자료로만 선택.

**결과**: 2024년 **0.708**(v6 대비 차이의 95% 구간 [0.003, 0.008]), 2025년 0.697, 2026년 0.637.
v8 자체의 95% 구간은 [0.700, 0.717]이라 "0.7을 확실히 넘는다"고는 쓰지 않았습니다.

## v9 — 공고일 누락 보완

**발견**: 새로 확보한 실제 사건 5건으로 검색 결과를 확인하던 중, 거절된 LIKEHUR(43류)의 인용상표가
후보에 없었습니다. 그 상표는 공고일 칸이 비어 있어 "출원일 이전 공개" 조건에서 탈락하고 있었습니다.
풀 63만 행 중 약 21만 건이 같은 상태였습니다.

**원칙**: 날짜를 추정하지 않는다. 등록일을 공고일 대신 쓰지 않는다.

**한 것** (`publication_dates.py`)
- KIPRIS 원본 엑셀 44개의 해당 셀과 공식 서지 화면 12건에서 공고일을 확인.
- 근거마다 파일 경로·행·SHA-256 기록. 출원번호·이름·출원일이 풀과 일치할 때만 채택.
- 585건 복원(출원공고일 582, 등록공고일만 확인 3). 색인 420,726 → 421,311건.
- 모델 구조·하이퍼파라미터는 v8 그대로 고정하고 한 번만 재학습. 5건은 학습·보정·평가에서 제외.

**결과**
- LIKEHUR의 인용상표가 후보 3위로 검색됨. 예측 확률 0.164 → 0.192.
- 전체 성능은 사실상 그대로: 2024년 0.7083 → 0.7088(차이의 구간이 0 포함), 2025년 0.6972 → 0.6964,
  2026년 0.6367 → 0.6298.
- 라벨이 있는 25만 건 중 32,723건의 검색 특징이 바뀜.

**판단**: 검색 누락 복구는 확인됐지만 전체 성능 향상은 확인되지 않았습니다. 그래서 서비스 모델은
교체하지 않았고, 남은 약 20만 9천 건은 공식 자료를 다시 수집해야 하는 과제로 남겼습니다.

## 전체를 통해 지킨 원칙

1. **이전 버전은 덮어쓰지 않는다.** 새 실험은 새 폴더에서, 이전 모델·자료는 해시로 보존.
2. **규칙을 먼저 적고 점수를 나중에 본다.** 후보·선택 기준·배포 조건을 `protocol.json`에 고정.
3. **평가 자료로 고르지 않는다.** 선택은 2023년, 2024년 이후는 비교만.
4. **이미 본 자료를 새 자료라고 부르지 않는다.** 2024–2026년은 '개발 자료 사후 비교'로 표기.
5. **개선이 확인되지 않으면 배포하지 않는다.** v4, v5, v9가 그 경우.
6. **모르는 것을 지어내지 않는다.** 미매칭은 '식별력 높음'이 아니고, 빈 공고일은 추정하지 않는다.
